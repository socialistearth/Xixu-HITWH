## 教务数据如何读取

点击“同步教务”，或开启启动同步且达到间隔时，独立 WebView 按已验证的个人课表、考试详细查询、期末成绩页面顺序读取。考试和成绩通过页面上实际存在的学期控件和查询按钮获取当前学期结果，不猜测隐藏接口、不枚举地址、不自动翻页。

课程页面默认学期相符时直接读取；需要调整学期时触发一次原有学期控件。考试/成绩页面各提交一次当前学期查询，页面之间间隔 1.8 秒，单类等待上限 20 秒。同步不并发、失败不循环重试。学校网页资源及其查询操作仍会正常产生网络请求。

首次使用或会话失效时，应用自动进入 VPN 的 CAS 统一认证，填写已保存的学号和密码，再进入教务系统的统一认证入口。学校要求 APP 或短信验证码时弹出输入框；发送及提交验证码均需用户操作。图片或滑块验证复用学校页面弹窗。选择“仅本次登录”，不自动信任设备。登录成功后自动继续同步，取消登录不再查询。自动动作有次数及超时限制，不循环提交密码。

“手动导入”保留为页面变化或自定义修正时的备用入口。自动同步会保留已有手动修正；其他当前学期数据使用学校本次结果更新，其他学期数据不受影响。没有发布数据的空表不删除缓存。

目前确认学校课表的文本格式和表格结构；考试/成绩确认了空表、表头和查询控件，尚无非空真实样本。页面结构改变、分页或跨域框架不可读时会保留缓存并提示。

## 提醒的准确性与权限

- 课程闹钟：当前选择的教学周 + 星期 + 校历日期 + 确认过的作息时间。
- 考试闹钟：教务页面给出的具体日期和时间。缺失日期不推算。
- 所有时间按 **Asia/Shanghai（北京时间）** 处理，不随手机当前时区错误偏移。
- 闹钟是本次具体日期的一次性提醒，支持提前 0 / 5 / 10 / 15 / 30 / 60 / 1440 分钟。
- Android 12+ 需要“闹钟和提醒”特殊权限；Android 13+ 需要通知权限。首次授权之后再次点击设置。
- 闹钟使用 `AlarmManager.setAlarmClock`、原生前台媒体服务和闹钟音频；最多响铃 10 分钟，可在通知或闹钟页关闭。
- Android 14+ 是否弹出全屏页由系统的全屏通知权限决定；未获准时依然尝试声音和通知提醒。
- 重启后重新注册仍在未来的闹钟；系统强行停止应用、撤销权限、厂商后台限制、关闭设备或关闭闹钟音量可能影响提醒。**本次未在手机上验证可靠性。**
- 点击日历提醒会打开系统日历的新增事件页面；需要用户在日历里确认提醒并保存。本应用不申请读写全部日历的权限。
- 课表变化不自动修改已经设好的闹钟。在用户页的“查看已设置的闹钟”中取消，再为新时间设定。

## 绩点

“官方平均绩点”只展示明确识别到的学校页面汇总，不用分数猜测绩点。
“本地加权参考”仅根据当前学期已导入课程的学分与绩点计算，缺失字段的课程不参与；不处理学校的重修覆盖、免修、排名规则，不等同于官方 GPA。若学校汇总包含多个学期，其统计范围需以页面说明为准。

## 构建 APK

最低 Android 8.0（API 26），compileSdk / targetSdk 为 35。界面需要较新的 Android System WebView（建议 Chromium 108 或更高）；请更新系统 WebView 后使用。

工具链固定为：JDK 17、Gradle 8.11.1、Android Gradle Plugin 8.9.2、Android SDK Platform 35、Build Tools 35.0.0。项目没有额外 Android 运行时库。教务与新闻均不依赖自建服务器；新闻需在手机填写兼容 Chat Completions 的模型 HTTPS API 地址、模型 ID 和 API Key，密钥通过本机加密存储保存。

### 本地构建

安装 Android Studio 和上述 SDK，并安装 Gradle 8.11.1。设置 `ANDROID_HOME`，或在项目根目录的 `local.properties` 中设置自己的 `sdk.dir`。在包含 `settings.gradle` 的目录运行：

```bash
gradle --no-daemon :app:assembleDebug :app:lintDebug
```

APK 输出位置为：`app/build/outputs/apk/debug/app-debug.apk`。

**源码包未包含 Gradle Wrapper 二进制。** 不要运行不存在的 `./gradlew`。有 Gradle 后可自行生成：

```bash
gradle wrapper --gradle-version 8.11.1
```

本次交付的是使用固定新密钥签名的 release APK。源码包不包含签名私钥；私钥与密码另存于签名备份包，后续覆盖更新 0.5.x / 0.6.x / 0.7.x 必须使用该密钥。自行构建的 debug APK 与交付版本签名不同，不可直接覆盖。

构建同签名版本：先 `gradle :app:assembleRelease`，再运行 `bash tools/sign-release.sh /已解压的签名备份目录 /输出.apk`。保持默认包名，递增版本号。请勿把签名备份上传公共仓库。

### GitHub Actions 构建

将项目目录中的内容放到自己的 GitHub 仓库根目录。仓库已包含 `.github/workflows/android.yml`，可手动运行 **Android APK**。成功后从 Artifacts 下载 `Xixu-HITWH-debug-apk`。

工作流没有执行过，不代表已有云端构建成功的 APK。运行工作流无需学校账号，不应向 GitHub 上传自己的密码或 Cookie。
