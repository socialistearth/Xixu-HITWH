# 汐序 0.7.3：资源页路径与新闻链接修复

## 手机反馈确认了什么

0.7.2 的登录诊断显示：统一认证提交后已到资源门户，文档完成加载，存在两个可见的“校主页”卡片且标题、地址均匹配，但页面被归类为 `vpnOther`，资源打开次数为 0。旧逻辑仅接受 VPN 根路径 `/`，因此在实际手机使用的其他路径下提前返回 `unknown`。不是账号未提交，也不是找不到卡片。

新闻截图显示：校主页共 323 个页面链接，近期未转换的文章标识 18 个，缺少标题 0 个，尚未调用模型。这次结果明确属于新闻地址识别未完成，不能解释为模型认为没有入选消息。截图未包含原始链接文本，不能由这份截图确定每条地址采用哪一种写法。

## 修复

- 在严格的官方 VPN 域名内，通过精确资源卡片及目标地址识别资源门户，支持非根路径；认证页面与代理内的其他站点不作为资源门户。教务与新闻使用同一套修复。
- 原生跳转继续核对当前页面及已核实的目标地址，自动打开“校主页”或“新教务系统”；不依赖学校页面的新窗口行为。
- 新闻读取支持校主页文章的绝对原站链接、协议相对链接、根相对链接、普通相对链接和已改写的 VPN 链接。只对已经核实映射的 `www.hitwh.edu.cn`、`news.hitwh.edu.cn` 进行转换，不推测其他域名的 VPN 地址。
- 以原生 WebView 当前地址核对实际页面，兼容 WebVPN 对网页中地址的改写；正文仍必须与本次排队的文章相符。
- 获取失败后标题显示“校园消息获取未完成”，并明确已停止，避免界面仍显示正在获取。

已有的串行访问、单次最多 20 篇、七天范围、去重和自动任务静默失败规则保持。未调用模型就失败的获取不会将文章标记为已处理，也不需要清空旧新闻缓存。

## 安装与验证范围

应用名“汐序”，包名 `edu.hitwh.fieldnote.news`，versionCode 13 / versionName 0.7.3。使用原固定签名，直接覆盖安装 0.7.2，保留账号配置、课表、备忘录与新闻缓存。

这次根据手机日志和截图定位，以离线页面复现及验证，不重新登录学校、不调用付费模型。没有连接用户手机运行；离线回归通过不等于已经验证这台手机完成整条抓取流程。

验证结果：

- 全量 JavaScript 测试 123 项通过；教务访问分类 39 项 Java 检查、5 项 JS 测试通过。
- 使用 0.7.2 APK 内原始脚本，与新版在同一 360px 资源门户样例上对比。样例含 29 个二级标题、两个可见精确目标卡片及 0 个 iframe；非根路径为合成样例，未假称已经知道手机的实际路径。旧版返回 `unknown`，新版对新闻和教务均返回正确资源地址。
- `tests/fixtures/news-home-raw-18.json` 使用模拟文章编号与已核实的学校地址形式。同一批 18 条链接：旧版未转换 18、入队 0；新版未转换 0、入队 18。没有远程抓取这 18 篇模拟文章。
- 独立复查原始链接、原生当前地址、正文 `page.psp` 跳转及同篇校验的衔接通过；链接仍只用于本地导航，不发送给精选模型。
- Android 清理构建后的 `assembleRelease` 与发行版关键 Lint 检查通过。
