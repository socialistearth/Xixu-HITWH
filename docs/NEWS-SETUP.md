# 汐序：手机获取校园消息（更新至 0.7.6）

汐序现在由手机直接通过校园 VPN 进入“校主页”，读取页面中的新闻链接并调用你配置的模型进行精选。新闻来源从 VPN 门户内的“校主页”开始发现，只跟随实际发现的文章链接；首页列出的文章可能位于不同的 VPN 代理路径。App 不再从旧版预置的两个公开站点开始抓取，也不需要部署新闻服务器。

## 从 0.6.0 更新

直接覆盖安装最新发行版 APK，不要先卸载旧 App。0.7.0 沿用 `edu.hitwh.fieldnote.news` 包名与固定签名，保留原来已存的课程、考试、成绩、备忘录、闹钟和本机新闻。系统中应用名称仍为“汐序”。

旧新闻服务器地址与访问密钥不再用于获取新闻，需要在手机上重新填写模型配置。旧服务器上的全部历史不会自动迁入手机；App 原有新闻缓存最多保留 90 份，并不能代替服务器数据库备份。

尚在使用 0.4.x 包名的用户不能覆盖更新或自动迁移旧数据。这不影响已经安装 0.5.x / 0.6.0 的用户。

## 首次设置

1. 在“用户”中确认学校学号与密码已保存。新闻与教务共用这组学校登录资料。
2. 打开“用户 → 校园消息”，填写下面的模型资料。
3. 点击“保存新闻设置”。保存只更新配置，不会立即抓取新闻。
4. 回到新闻列表，点击“立即获取”。按钮下会显示进度和步骤；需要本人验证时，点击变为“手动验证”的按钮，在学校网页完成验证后等待结果。

| 设置 | 填写内容 |
|---|---|
| 模型 API 地址（HTTPS） | 服务商提供的兼容 Chat Completions 的 API 根地址，例如 `https://api.example.com/v1`。填写模型服务地址，不是原来服务器的公网 IP。 |
| 模型名称 | 服务商提供的模型 ID，需与该地址支持的模型一致。 |
| 模型 API 密钥 | 模型服务商提供的 API Key。不是原新闻服务的 `NEWS_API_TOKEN`，也不是学校密码。 |
| 关注方向 | 可选，填写专业、兴趣或重点关注的信息。默认按 2026 年 9 月入学的本科生判断年级与学期。 |
| 每日自动获取 | 开关。开启且学校资料、模型配置完整后，手机才会安排后台任务。 |
| 自动获取时间（北京时间） | 默认 19:00，可自行修改。按北京时间安排，不随手机当前时区改变含义。 |
| 获取成功后通知我 | 可选。关闭后仍保存成功获取的新闻，打开新闻页即可查看。 |

原 Docker 的模型资料分别位于 `config.toml` 的模型配置和 `.env` 的 `LLM_API_KEY` 中，可以在自己的设备上核对后填入手机。不要将学校密码、模型密钥或完整配置截图发送到公开渠道。

学校账号、密码和模型密钥通过本机加密存储保存。模型只接收待精选的文章文本及关注方向，不接收学校账号、密码或 VPN Cookie。调用模型会使用你填写的服务商 API 额度。

## 立即获取与学校验证

“立即获取”不受每日自动任务次数限制。正在获取时再次点击不会并发启动另一轮。已有新闻保留为离线缓存；重复发现的已处理文章不会因为手动获取而重复调用模型。

正常登录过程在主界面的隐藏任务中完成，原按钮转圈，下方显示进度条与当前步骤，可以切换选项卡继续使用。需要验证码、图片验证或其他本人操作时，按钮变为“手动验证”，点击后才打开学校网页。完成验证后自动继续；关闭尚未完成的网页会回到等待验证状态，可以再次点击按钮。手动任务最长等待 15 分钟，超时保留原有新闻。

从 VPN 资源门户进入教务时，App 会自动寻找并打开“新教务系统”；获取新闻时则寻找“校主页”。无需每次在截图中的资源卡片页面手动点击。学校页面发生变化或出现需要本人确认的步骤时，仍可能需要打开验证页面。

新闻详情中的“查看学校原文”：VPN 地址使用 App 内学校浏览器，以继续使用会话；公开 HTTPS 原文使用系统浏览器。若 VPN 会话失效，学校仍可能要求重新验证。每条精选还提供“复制链接”。0.7.6 支持校主页所列两新闻网原文，VPN 技术故障时仅对明确关联的同篇新闻尝试一次官方 HTTPS 正文。

“更新列表”只更新本机显示，不登录学校、不抓取新文章、不调用模型；需要新一轮精选时使用“立即获取”。

## 自动获取的实际运行方式

手机按你设定的北京时间每日安排一次后台任务。自动任务遇到网络异常、登录过期且需要验证、正文读取失败或模型错误时安静结束，不弹验证码、不展开网页、不发送失败通知。之后可在方便时主动点击“立即获取”处理。

Android 的后台任务可能受省电模式、休眠、网络、厂商后台管理影响，因此设定时间是计划开始时间，不保证整点准时完成。请在手机系统设置里允许汐序后台运行；部分手机还需要允许自启动或将电池策略设为“不限制”。不同品牌的选项名称可能不同。

强行停止 App 后，系统会暂停它的任务，重新打开汐序后才会恢复安排。关机、无网络或系统禁止后台运行时无法获取新闻。不要为了排查定时问题反复点击“立即获取”，可以先核对后台限制与本次运行状态。

自动失败不会删除离线新闻。原来“启动时自动同步教务”的开关与最短间隔依然单独控制教务查询，不等于新闻的每日定时开关。

## 卸载旧 Docker

先在手机完成一次获取，确认新功能可用，再按 `docs/UNINSTALL-DOCKER.md` 停止旧新闻服务。默认卸载只移除这个 Compose 项目的容器和网络，保留新闻数据卷与配置，方便回退；需要彻底删除时，指南另有单独步骤。

本次更改不需要在服务器部署新版本，不需要维持原新闻接口、公网 IP 连接或专用 HTTPS 证书。

后台限制参考：[Android 官方 Doze 与应用待机说明](https://developer.android.com/training/monitoring-device-state/doze-standby)。系统会延后网络与 JobScheduler 任务，所以设定的是计划获取时间。

## 本次已核对的范围

2026 年 9 月 21 日已在真实浏览器中经校园 VPN 进入资源门户，打开“校主页”，并读到先前失败的《关于清理废置（弃）自行车的通知》正文。该文章的 `.htm` 地址会跳转到同一篇文章的 `page.psp` 页面，本次已按实际返回情况处理。资源卡片的真实 DOM 结构已作为离线回归样本，覆盖卡片标题本身没有跳转链接的情况。

也已核对资源门户的“新教务系统”入口能够进入教务统一身份认证页面；这一观察不代表已完成本轮教务登录和全量查询。发布前未在真实 Android 手机上验证每日后台执行，未调用付费模型 API。手机实际省电策略与学校后续验证步骤仍需以使用时的表现为准。
